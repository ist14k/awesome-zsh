Awesome Zsh

Offline manual · version 1.0.0

Fast, pinned shell ergonomics with explicit network operations and a rollback-safe installer.

Installation and architecture

Verify the release checksum before running install.zsh. For a trusted checkout, run:

zsh install.zsh
zsh install.zsh --dry-run
zsh install.zsh --yes --no-bootstrap

Options are --dry-run, --yes, --force, --no-bootstrap, and --help. The installer stages and validates a complete configuration, backs up replaced files, and then commits it. It copies release files; the installed configuration is not a symlink to a clone.

LocationPurposeTypical path
$ZDOTDIR/.zshenv, .zshrc Small entry points~
$XDG_CONFIG_HOME/zsh Versioned configuration, manual, pins~/.config/zsh
$XDG_CACHE_HOME/awesome-zsh Regenerable cache~/.cache/awesome-zsh
$XDG_DATA_HOME/awesome-zsh Managed plugin/tool data~/.local/share/awesome-zsh
$XDG_STATE_HOME/awesome-zsh Backups, locks, state~/.local/state/awesome-zsh

init.zsh loads focused files from conf.d, lifecycle helpers from lib, pins from lock files, and finally the untracked local.zsh. Copy local.zsh.example to add machine-only settings.

Commands, aliases, and functions

zsh-bootstrap [--force]
Install or repair pinned optional plugins and tools. This is an explicit network operation; --force reinstalls.
zsh-update [all|config|plugins|tools|rollback]
Update one managed layer, all layers, or restore the latest backup.
zsh-doctor [--benchmark]
Check paths, pins, plugin state, and executables. Benchmark mode also reports startup time.
zsh-reload
Replace the current interactive shell with a clean Zsh process.
zsh-doc [--path|--check]
Open this file, print its path, or verify that it is readable and belongs to the installed version.

Editing experience

Suggestions prefer shell history, then completion candidates. Accept only what you want; suggestions never execute themselves. Existing paths are teal and underlined, while valid path prefixes are lavender. Vi mode gives command and insert editing; fzf-tab provides interactive completion. Starship renders the Catppuccin prompt. Existing fnm initialization remains responsible for Node.js selection.

Aliases and helper functions are deliberately kept in the readable conf.d files. Entries carrying a # doc: marker are public and have a matching marker in this manual.

Plugins and tools

Plugin revisions are recorded in plugins.lock; tool versions live in versions.lock and Mise lock/config files. Bootstrap installs exactly these revisions under the data directory. Typical components are zsh-autosuggestions, fast-syntax-highlighting, fzf-tab, Starship, Atuin, fzf, Mise, and retained fnm integration.

Atuin is local-only: syncing, accounts, and remote history are disabled. History and Atuin databases are runtime data and never enter an archive.

Interactive startup reads local files only. It never runs Curl, Git, a package manager, update checks, or any other network action.

Bootstrap, updates, and offline use

The first interactive run may offer or trigger the one-time bootstrap policy recorded by the installation. It uses a lock so concurrent shells cannot corrupt shared state. If bootstrap is offline or interrupted, the base shell still loads and the operation can be retried with zsh-bootstrap.

Updates are manual and transactional. zsh-update config handles release configuration, plugins resolves pinned plugin assets, and tools handles pinned executables. Use all for all three. Failed validation preserves the installed version.

For permanent offline use, install with --no-bootstrap. Completion, Vi editing, aliases, functions, this manual, and fallback prompt behavior remain available; missing optional enhancements are reported by zsh-doctor.

Recovery and rollback

  1. Start a clean emergency shell with zsh -f.
  2. Run zsh-update rollback if the command can be loaded.
  3. Otherwise inspect the newest backup below ${XDG_STATE_HOME:-$HOME/.local/state}/awesome-zsh and copy its files back to their original paths.
  4. Run zsh-doctor, then open a new shell.

Do not delete backups until the restored shell has started successfully. Installer failures should restore the pre-install files automatically.
